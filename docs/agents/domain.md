# Domain Docs

工程技能在探索代码库时如何消费本仓库的领域文档。

## 探索前先读这些

- **`CONTEXT.md`** — 根目录下的领域术语表（如果有）
- **`docs/adr/`** — 先阅读与当前工作相关的 ADR

如果这些文件不存在，**静默继续**。不要提示缺失，也不要主动建议创建。（`/grill-with-docs` 会在术语或决策明确时按需创建它们。）

## 文件结构

单上下文仓库：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-xxx.md
│   └── 0002-xxx.md
└── src/
```

## 使用术语表中的词汇

当输出中出现领域概念时（issue 标题、重构提案、诊断假设、测试名），使用 `CONTEXT.md` 中定义的术语，不要换用同义词。

如果需要的概念不在术语表中，说明可能：
- 你在发明项目不使用的语言 → 重新考虑
- 确实存在缺口 → 记录下来供 `/grill-with-docs` 使用

## 标记 ADR 冲突

如果输出与已有 ADR 矛盾，显式指出而非静默覆盖：

> _与 ADR-0007（事件溯源订单）冲突 — 但可能值得重新讨论，因为…_
